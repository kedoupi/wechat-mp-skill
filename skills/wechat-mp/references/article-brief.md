# Article brief（写前任务书）

在写正文之前，先落盘 `brief.md`（可与 `article.md` 同目录）。**禁止跳过任务书直接长文。**

## 必填字段

| 字段 | 说明 |
| --- | --- |
| 目标读者 | 谁、什么情境下打开这篇 |
| 真正问题 | 读者读完前未解决的那个问题（一句话） |
| 读后收获 | takeaway / 可执行动作 |
| 核心判断 | thesis：你的立场，不是中立复述 |
| 新增价值 | 相对已有通识，这篇多说了什么 |
| 适用边界 | 什么人/场景不适用 |
| 最强反方 | 反对意见一句话 + 你的回应方向 |
| 框架 | 见 `frameworks.md` 四选一 |
| 个人材料 | `available=true/false`；仅用户本轮明确提供的经历可用 |

## 简短模板

```markdown
# Brief

- 读者：
- 问题：
- 收获：
- 判断：
- 新增价值：
- 边界：
- 反方：
- 框架：干货清单 | 观点判断 | 热点解读 | 复盘
- 个人材料：无 / 有（列出要点，禁止扩写未提供细节）
```

## 规则

- 个人材料 `available=false` 时：可以写第一人称**判断**，禁止编造亲历、同事、客户对话、时间地点感官细节。
- 需要故事开场但无材料：改用观察 / 问题 / 判断开场。
