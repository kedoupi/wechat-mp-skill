# Editorial review（五项 + 阻断项）

初稿写完后**必须自检**；不通过则直接改稿，不得把未过审稿称为「成稿」。

## 五项（各 1–5，均分 ≥4 且单项 ≥3 才可 pass）

| 维度 | 问自己 |
| --- | --- |
| 准确 | 数字、引述、时效是否可支撑？不确定是否已降级表述？ |
| 观点 | 有没有核心判断？是否比通识多一句「你的线」？ |
| 有用 | 读者能否据此做一个动作或做一个决策？ |
| 合声 | 是否符合 style / 账号定位？有没有油腻营销腔？ |
| 好读 | 手机阅读：开头快入题？段落短？小标题服务结构？ |

## 阻断项（任一命中 → 必须改）

1. **编造亲历**：未在 brief 中记录的用户经历、客户对话、采访。  
2. **无来源硬数字**：精确百分比、融资额、排名等无法核对。  
3. **答非所问**：正文不回答 brief 里的「真正问题」。  
4. **虚假承诺**：保证收益、包过、医疗/法律结论。  
5. **把模型记忆标成核实事实**。

## 标题与摘要

- 主标题：对象 + 利益点；备选 2 个。  
- 摘要：约 40 字内，不靠震惊体。  
- 不要为打开率编造数字。

## 决策

- `pass` → 写入 `article.md`，更新 manifest `status.article=done`  
- `revise` → 改稿后重跑本清单（最多两轮，仍不稳则缩小主张）  
- `needs_input` → 仅当用户坚持要个人故事但材料不足
